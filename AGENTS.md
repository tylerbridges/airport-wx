# Repository workflow

## Product goal

A user should feel confident they're aware of any potential disruption, weather or not. Clean by default (traveler language), detail behind toggles (aviation mode), and never silently wrong (a source failure or stale data is always stated). This governs every choice.

## Workflow

airport-wx is the Airports app: a static page showing major-weather and delay risk at major US airports. A GitHub Actions job polls the sources every 10 minutes, computes risk, and deploys `site/` to GitHub Pages.

- Work directly on `main` unless asked otherwise. Start with `git status`; when clean, `git pull --ff-only origin main`. Never discard pre-existing changes.
- Commit task-scoped files with a descriptive message and push with `git push origin main`. Never force-push.
- No dependencies anywhere: Node built-ins only for the poller (Node 20), plain HTML/CSS/JS for the site, no build step.
- Bump the `app.js?v=` number in `site/index.html` whenever `site/app.js` or the page's CSS changes.
- Service worker (`site/sw.js`, README "Service worker"): bump its `VERSION` on every change to the file and re-pin the hash in `tools/sw.test.mjs` (the test prints it). Its caches are `awx-shell-*`/`awx-data-*` only; never delete other caches (the radar's `awx-mrms-1`, the weather site's `wx-*`) and expect ours to vanish (the weather site's root `/sw.js` clears the origin). Data is network first with the saved copy only on failure (`X-AWX-SW: fallback` → "Offline · last checked …"); never cache scenarios, `trips.json`, calendar/personal data or anything new under `data/` without adding it to its routing and tests. Files cached by `?v=` are immutable: always bump `?v=` when a file changes. `?nosw=1` skips it; `?test=` pages and `check.html` bypass it.
- Risk rules live in `poller/risk.mjs` and are documented in the README ("Risk levels"). Change both together and update `poller/risk.test.mjs`.
- If the shape of `status.json` changes, update `site/app.js`, the README schema, `site/split.js` when the field is detail-only (README "status.json"; `tools/split-equivalence.test.mjs` must pass), and regenerate the committed fallback with `node poller/poll.mjs --fixtures --out site/data/sample.json`.
- `site/data/status.json`, `summary.json` and `airport/` are generated and git-ignored; never commit them. Only the summary and airport files are published, plus — temporarily, until 2026-10-13 (TODO in `poll.yml`) — a `status.json` without `hubResearch` for already-open v84/v85 tabs and the previous live relay; history reads the full `.cache/status.json`.
- The workflow records every poll to the `history` branch (`poller/record.mjs`, `poller/history.sh`): `truth/` (observed outcomes), `forecast/` (hourly predictions) and `raw/latest/` (first 200 KB of each source's latest raw response + `sources.json`). Never commit to `history` by hand or force-push it. To check a live response format (LAMP, ATCSCC, TCF and CWA parsers were written from documentation), read `raw/latest/` on that branch, e.g. `git fetch origin history && git show origin/history:raw/latest/sources.json`. If a format differs, fix the tolerant parser in `poller/sources.mjs` and add the real sample as a fixture.
- Program causes live in `poller/cause.mjs`, FAA closure/NOTAM handling in `poller/notam.mjs`; both are documented in the README and unit-tested. A full closure holds its whole window (`risk.mjs` `closureSpan`, delay override "closure"). Related-airport spillover is research-only (poller/hubs.mjs, core.mjs hubResearch, record.mjs history). Never applyCascade in live assembly or use research signals to raise airport/trip risk. Preserve negative controls, unavailable coverage, source health, issue times and baseline forecasts; see ROADMAP.md before promotion.
- Flight restrictions: FAA TFR list/XML fetching in `poller/notices-poll.mjs`, parsing/distance in `poller/tfr.mjs`, per-airport hourly scoring in `poller/notices.mjs`, display in `site/notices.js`. Quality lives in `status.noticeSources.tfr`. Airport NOTAM fetching was removed; retain the separate `poller/notam.mjs` NAS closure parser.
- Additional SIGMET advisories: `poller/aviation-advisories.mjs` handles severe turbulence/icing and volcanic ash as informational airport/trip context, preserving altitude and exact valid times. They never change risk levels or delay probabilities. `isigmet` is fetched by the build; relay fallback expires per item.
- aviationweather.gov does not allow CORS, so the browser must never call it. The page reads only files under `./data/` (summary.json and airport/<IATA>.json, the airport list, the global `wx/` shards, scenarios, `config.json`) and the live relay that `config.json` names.
- Traveler text comes from `poller/plain.mjs` (`site/plain.js` is a byte-identical copy: after editing, `cp poller/plain.mjs site/plain.js`; a test fails if they differ). Traveler strings never carry raw codes (CLSD, BKN008, TEMPO, PROB30, 2130Z…) and never claim certainty ("possible", "likely").
- `site/data/wx/` (global METAR/TAF shards from `poller/global.mjs`) is generated each poll and git-ignored. `site/data/airports-all.json` is rebuilt weekly by `.github/workflows/airports.yml`; locally `node tools/build-airports.mjs --fixtures` rebuilds the small fixture version.
- Test scenarios: fixture sets in `poller/scenarios/` (README "Test scenarios"), 30 of them in five menu groups — Delays & programs: all-clear, minor-delays, gdp-low-clouds-sfo, recovering, all-quiet-holiday-peak, lax-ga-only-closure, hub-cascade; Weather: northeast-storms, winter-deicing, hurricane-closure, thunderstorm-ground-stop, winter-storm-gdp, full-closure, turbulence-advisory, icing-advisory, volcanic-ash-advisory; Non-weather: airline-it-outage, atc-staffing, atc-staffing-ground-stop, vip-tfr; Trips: trip-misconnect, trip-gdp-destination, trip-tight-connection, trip-all-clear, trip-weather-concerns, trip-origin-ground-stop; System health: live-relay-down, model-fallback, source-outage, stale-data. After changing the poller, risk rules, the delay model (a retrain can move delay words: new scenarios pin `at`) or a scenario, run `node tools/build-scenarios.mjs` and commit `site/data/scenarios/`. Add a scenario (with assertions in its scenario.json) for each new kind of disruption. The app opens them from Menu → Test scenarios (`site/testmode.js`, `// scenarios hook` in nav.js); nothing is saved while one is open.

- Live relay (README "Live relay"): `worker/worker.mjs` is a Cloudflare Worker that overlays fresh METAR/TAF/SIGMET/FAA/NWS on the last build. `.github/workflows/worker.yml` deploys it on every push to main that touches `worker/**`, `poller/**` or `airports.json` (and on manual dispatch); it skips with a notice until the repo secrets `CLOUDFLARE_API_TOKEN` (Account → Workers Scripts → Edit) and `CLOUDFLARE_ACCOUNT_ID` exist (Settings → Secrets and variables → Actions). The poll workflow then writes `site/data/config.json` with the relay URL (committed default `{"liveUrl":null}`). Modules the worker imports (`poller/core.mjs` and what it imports) must stay pure: no `node:` imports (`worker/pack.mjs` refuses them). Test locally with `node worker/dev.mjs serve`.

- Delay model (README "Delay model"): features live in `poller/delay.mjs` (shared by training, the poller, the relay and the page's data). After changing features, `SPEC`, the target, `poller/risk.mjs` rules or `tafHourParts`, run the "Train delay model" workflow (`.github/workflows/train.yml`) so `site/data/model/` matches; bump `SPEC` when old models can't be scored correctly (they then fall back). Never commit or ship a `model.json` that failed the safety gate (test Brier skill vs climatology > 0 and better than the rule-level mapping); only the workflow writes `site/data/model/`. `node tools/train.mjs --fixtures` must keep running end to end. UI is in `site/delay.js`, `site/accuracy.html`, `site/accuracy.js`; app.js/index.html only carry `phase3 hook` lines.
- Device calendar import: `site/trips-parser.js` mirrors pure `poller/trips.mjs` except the privacy reexport path (`./trip-risk.js?v=4`); sync after changing the parser, and keep the normalization test passing. `site/trip-import.js` strips file content down to airport codes, scheduled times and zone hints, deduplicates matching flights, and chooses the next flight by schedule. Files stay in memory until explicit save; never upload a file, URL, UID, name or booking detail. Local imports are snapshots with no sync.
- Private calendar links: `site/calendar-link.js` keeps a per-device connection in `awx-calendar-link`; `worker/calendar.mjs` handles stateless `POST /calendar`. Only allowlisted HTTPS iCloud/Google subscription URLs and redirects may be fetched; cap request/calendar bytes and time. Never log/cache/publish a link, raw calendar, personal field or per-device schedule. Preserve scheduled airport/time-only responses, foreground refresh, stale qualification, deduplication and disconnect. Flighty flight/friend sharing pages have no verified calendar export and must receive honest subscription-link guidance. `worker/calendar-airports.mjs` is replaced at packaging with the global name/time-zone lookup.
- Trips (README "Trips"): `poller/trips.mjs` (ICS parser), `poller/trips-poll.mjs` (fetch, trip airports, trips.json), `poller/trip-risk.mjs` (concerns; `site/trip-risk.js` is a byte-identical copy: `cp poller/trip-risk.mjs site/trip-risk.js`), `site/trips.js` (page: Your trips, the Trips tab via `AWXTrips.render(container)`, trip sheet, editor), hooks marked `// trips hook` in app.js, index.html, poll.mjs, check.js, settings.js and the workflows. Every trip airport (origin, connections, destination) joins the full pipeline for that run, even non-major ones (`trip: true` in status.json). Never publish identifying flight details: `site/data/trips.json` holds only airport codes, times and salted-hash ids — no flight numbers, names, confirmation codes, seats, notes or emails — and the `FLIGHTY_ICS_URL` link is never logged or written to any public file (mask it). The flight calendar's event format is unverified: check `raw/latest/trips-sample.json` (redacted) on the history branch and keep detection tolerant.

## How the site works

- Live monitoring merges the original 32-airport baseline with scheduled-service US/territory airports having METAR capability (`poller/airports.mjs`; currently 588). The original baseline remains stable for fixtures, training, terminal maps and ADS-B monitoring. National NWS alerts use cached zone geometries; missing observations, forecasts or alert coverage must stay qualified/unknown. The Worker packages expanded metadata as `airport-catalog.mjs`. See README “Search and the full airport list”.

- Navigation shell (README "Navigation and Settings"): `site/nav.js` (glass tab bar Airports / Trips / Map with the hash as state, round search button, header buttons, menu popover, theme) and `site/settings.js` (Settings sheet and its pages), shared helpers in `site/navui.js`, check-page assertions in `site/navcheck.js`. Settings read and write only `site/prefs.js`; day-of trip airports join My airports temporarily without changing stars or reorder persistence; favourites stay in `awx-favs` (changed through `AWXApp.setFavs`). Existing ids are kept, so `app.js` and `searched.js` don't know about the shell; its hooks are marked `nav hook`.
- The status bar area is covered by a solid `body::before` strip in `--bg` (height = top safe-area inset, z-index 8, under sheet scrims) so iOS shows an opaque status bar instead of a blurred band; keep it.
- The shared tab header and tab bar stay anchored. Downward panel scrolling compacts both bars; scrolling up, reaching the top or tapping a tab restores them. Keep 44 px touch targets, ignore resize-induced scroll anchoring, respect reduced motion, and show the bottom bar instantly when a sheet closes. The bar never translates or fades when hidden; use shared sheet-count notifications for every sheet, including Trips. In the navigation shell lock panel scrolling without fixing/repositioning the page body or calling window.scrollTo on dismissal. Trip sheets fill the viewport with safe-area padding. `.awx-panel` owns each tab's scrolling inside the same viewport footprint; save and restore panel `scrollTop`, never page `scrollY`. Tab changes use the history API to avoid native `#trips` anchor scrolling and fade without vertical transforms; respect reduced motion.
- `site/index.html` (markup + all CSS) loads `cats.js` (disruption categories, pure), `prefs.js` (settings state, classic script in `<head>`, `window.AWXPrefs`), `app.js` (everything rendered; classic script) and `searched.js` (search + non-major airports). Bump `?v=` on each file you change.
- Personal flights default off (`prefs.flights`). `site/flight-features.js` lazily loads Trips after opt-in; opt-out hides trip navigation/brief/highlights/routes and aborts reads and timers without deleting device data. Tests explicitly opt into Flights when testing trips.
- Settings state belongs to `site/prefs.js` (`getPrefs/setPref/onPrefs/DEFAULTS`, localStorage `awx-settings`); never write that key elsewhere. Ground stops and full closures can't be hidden.
- Category/level/impact rules for the page are in `site/cats.js` and must read back every poller reason (`tools/cats.test.mjs`); add a pattern there when `poller/risk.mjs` gets a new reason text.
- Default timelines roll over 36 elapsed hours: 12 hours before the current hour plus 24 forecast hours, with Now at slot 12. Tomorrow remains a local calendar-day view. Past hours come from `observed` (poll.mjs `// build2b hook`), the rest from `hours`; unavailable hours stay grey. The sheet's normal card sets the footprint; held hour previews scroll within that frame rather than reserving space for hidden cards. Keep the sections below stationary during previews and release.
- Main-page timelines preview after a 240 ms hold or immediately once a horizontal drag is established; vertical swipes scroll, and past/unavailable hours stay selectable during the drag; never prevent scrolling before activation or open the airport card after a hold. All touch timelines, including detail views, preview after the same 240 ms hold or an established horizontal drag; vertical movement cancels before activation. Mouse detail previews and navigation keys remain immediate; release, cancellation, lost pointer capture, or blur restores the normal view. Never keep a tapped hour selected or add a Back to now button.
- Airport details use a grouped menu of labeled navigation rows (44 px minimum targets) for Weather, Radar, Airport notices, Traffic, Today’s changes, Terminal map, Lounges and More details, only when the relevant data exists. Rows open full-height pages or existing map/radar viewers, never expandable cards. Active FAA restrictions, material notices (including unknown severity), weather warnings, current thunderstorm warnings and missing/stale source qualifications stay visible in the main sheet. Level-0 informational notices open from Airport notices. Preserve the airport sheet’s scroll position, restore the invoking row’s focus even after a live refresh replaces it, and keep the current popup page/scroll/focus through refresh. Radar and terminal maps load only after selection. The Weather page includes the airport-centered radar preview below current conditions; start it only when visible, reuse it through refresh/full-screen viewing, and tear it down when leaving Weather.
- Overnight hours (1:00–4:59 AM airport time, `outlook.js` `quietHour`; `outlookOpts` passes `tz: a.tz`): few flights, so delay chances never raise those hours or lead an outlook (`delay.js` `quiet`: card window, routine line, home-card line; Traveler mode). Weather, FAA restrictions and delays happening now still count. The timeline draws those hours faded, and their hour text says "Few flights".
- Airport sheet headline: always one top Now card (with the tappable current-conditions line under the Now status) (the old Now | Coming up pair is gone; a later, higher risk — CATS.restLayout "split" — appears in its own Looking ahead section below the timeline, directly before Today so far, using the same section header, card, timestamp column and compact rows as the log); it carries the status in large level-coloured type, and a separate "Looking ahead" section (`#lookingAhead`) below the timeline: the delay outlook (`site/delay.js` `outlookLead`) and the what-happens-next rows (`travelRows` in app.js); keep all forecast rows in that section without duplicating them in the Now card. Each fact shows once: the Now card's detail line leaves out reasons with their own card below (Weather warnings, Storms, FAA traffic notices), and one condition has one name (`oneEach` in app.js; the timeline's "Now · …" label reads the same reasons). Forecast windows and recovery times are on the hour (`hourFloor`: "7–9 PM"); FAA program ends stay exactly as the FAA gives them, through one helper (`faaUntil`) for the home card, the Now card and the log. The home card leads with outlook()'s current headline, or the FAA impact badge for an active program (e.g. Arrival delays ~2 hr 59 min), never both. Under a program badge, show the FAA end note once in bold neutral text followed by the cause in regular muted text; preserve exact scheduled ends. Main airport cards consolidate severity and impact into one badge (e.g. Minor: Gusty winds, High: Arrival delays ~2 hr 59 min); never add a separate status pill above it. Clear and unknown cards also keep one consolidated label, with unknown neutral. Main-card labels, reasons, accessibility labels and data-level reflect the current outlook only. Higher later risks and forecast timing appear in airport details under Looking ahead; hourly timeline colors still show their valid hours. Detailed airport headlines continue to omit the severity prefix. Forecast timing is bold neutral text, never a standalone risk-coloured line; later disruption summaries belong in airport details. Weather secondary/timing lines omit a repeated headline while retaining observation/advisory times and forecast windows. A quiet status with missing data reads "No disruptions reported", its qualifier said once in the small line above it. Below the timeline, "Today so far" (`logSection`) shows at most two of today's changes not already on the sheet (no warning that the Weather warnings card shows, no start of the headline's own program), then "+N earlier · see Today's changes", and is left out when none remain. Preview and full-log rows share compact spacing and a fixed timestamp column; history timestamps always include minutes (9:00 PM), respecting the selected 12/24-hour clock. Preview rows retain a 44 px touch area and open the full history. "Why this outlook" (analog, calibration, sources) lives only in More details, in both modes. One FAA program's end and average stay in the card's program line in both modes (no extra Scheduled end / direction rows); Aviation raw blocks under Delays & closures and Weather warnings show only when the raw text adds something to the plain line (`rawAdds`).
- Traveler airport details have no expandable cards, raw text or Pilot details in the sheet itself; technical detail lives behind the one "More details ›" row (a full-height page: Why this outlook, Pilot details, FAA plan & storm detail; raw text only inside its Pilot details card). Show one Operating normally status when the data is complete and quiet; Traveler mode omits routine delay commentary when conditions are normal; Aviation mode may show routine baseline detail. Active/upcoming disruptions retain timing, impact and warnings; missing, stale and hidden data must qualify any quiet status. Aviation mode also shows a static Aviation details subsection directly in the airport overview (METAR, TAF and available guidance). Secondary pages use a prominent page title and explicit Back to airport overview navigation in both modes. The check page scans every Traveler sheet for aviation codes.
- Change log and flight brief (README "Change log and flight brief"): `poller/changes.mjs` writes airport events (every observed hour-to-hour level change on the timeline must have a level event: `observedEvents` backfills the ones the poll-time level missed); `site/brief.js` renders the airport menu’s Today’s changes page. `site/trips.js` owns the compact departure-day flight brief and its trip sheet, grouping relevant itinerary concerns with unknown coverage retained. No standalone starred-airport brief. Event sentences and the brief never carry "%" or raw codes.
- Terminal maps and lounges (README "Terminal maps and lounges"): `site/terminals.js` provides the sheet's Terminal map and Lounges navigation rows and popup content and the full-screen gate-search map; hooks are marked `terminals hook`. `site/data/terminals/` is written only by `tools/build-terminals.mjs` (monthly workflow `terminals.yml`, one Overpass query per airport, ≥ 5 s apart, no retries; never loop it locally against the live API); keep the "© OpenStreetMap contributors" attribution with the link on both maps. `site/data/lounges.json` is hand-curated: every entry needs a `source` (operator page); set `verified` only after checking that page, and leave `confidence: "low"` otherwise (the UI then says "Check before you go").
- Airport overview sheets cap at 88% of the dynamic viewport, leaving the main page visible above them. A quick downward content flick at the scroll top must retain its initial distance and velocity, including when starting over a timeline; horizontal scrubbing and upward content scrolling remain separate. Keep the cap independent of loading/data length.
- New sheets use `site/sheet.js` `makeSheet` (drag / back / scroll lock); don't hand-roll swipe code. Use `AWXSheet.transfer` when opening an airport from Across the U.S. or another sheet, so delayed browser Back cannot dismiss the new view. Alaska and Hawaii regional headings omit “the”.
- Delay chances reach Traveler users only as words from `site/delay.js` `likelihood()`; never print a raw % outside Aviation mode and the accuracy page.
- The app is "Airports"; its identity (runway mark, `--brand` amber, own tab glyphs) is ours: no "Flighty" in UI labels (setup steps may name it).

## Decoded forecasts

- `poller/taf-periods.mjs` builds display-only forecast periods from the existing TAF interpretation; it never changes risk or delay scoring. `taf.periods` and global shard `tp` feed the Weather page and Pilot details. Preserve exact change windows, inherited temporary conditions, probability qualification, stale/missing decoding and visibility upper limits. METAR and TAF information buttons explain the report names to travelers; raw reports and flight categories stay in the existing technical areas.

## Checks before publishing

1. `node poller/run-tests.mjs` — all pass.
2. `node tools/build-scenarios.mjs` — runs every scenario through the real poller.
3. Serve `site/` (`python3 -m http.server -d site 8000`) and open `check.html?mock=1` headless; require `CHECK PASS`:
   `chrome --headless=new --disable-gpu --virtual-time-budget=30000 --dump-dom "http://localhost:8000/check.html?mock=1" | grep -o "CHECK [A-Z]*[ 0-9]*"`
   (it also renders `index.html?test=<each scenario>` at 390 px and fails on any console error).
4. Load `index.html` (and `?test=thunderstorm-ground-stop`) at 390 px in light and dark mode with no console errors.
5. After pushing: run the "Uptime monitor" workflow (or open `https://tylerbridges.github.io/airport-wx/check.html`) and require `CHECK PASS`.
- Never use Flighty's name, logo or branding; the look is "inspired by" only.

- Radar popup (README "Radar"): `site/radar/card.js` (menu-opened full-screen sheet, Weather-page preview, check rows), `site/radar/geo.js` (pure, `tools/radar.test.mjs`), hooks marked `// radar hook` in app.js, index.html and check.js. `site/radar/wx-radar.js` and `wx-vmap.js` are copies of the weather site's engine (github.com/tylerbridges/tylerbridges.github.io, commit `d4f012b`; its AGENTS.md "Radar tab" explains the engine): keep changes there minimal and listed in the file header, keep `geo.js` `DOMS` equal to the engine's, and bump `ENGINE_V` in card.js when they change.  Engine perf changes here (listed in its header): the loop holds during pan/zoom/fling, labels at up to 2x, memoised ready()/timeUi(). Never load the engine on the home list; tear it down when the sheet closes. Traveler mode shows no dBZ numbers. Live radar needs checking on a real network (NOAA S3, OpenFreeMap).
- Health (`outlook.js` `health`): FAA Command Center advisories (ATCSCC) come only from the GitHub build, so while the live relay's FAA status is fresh they may lag up to 3 h before an outlook counts as incomplete; the sheet's checked line then states their age (`advisoriesAge`). Every other required source keeps the 30-minute limit. Missing, failed or stale storm sources (SIGMET 30 min; SPC, LAMP, TCF, CWA 3 h) qualify quiet outlooks ("No disruptions reported · storm data unavailable"). ATCSCC program advisories come from the `adv_list` advisory list (README "Sources"); when nothing is parsed, followable or recognised, the source is degraded (ok with an error), never fresh. Forecast hours no METAR/TAF covers have level null ("No forecast", grey), never Clear.
- Airport-hour outlook is shared through `site/outlook.js`; Map and details must agree. Keep scheduled FAA end, published extension outlook and forecast improvement distinct. Missing/stale coverage stays unknown, never green.
- Map tab (README "Map tab"): `site/map.js` draws dots on a canvas over `site/map/vmap.js` (a copy of the weather site's `wx-vmap.js`, OpenFreeMap vector tiles; note any change at its top and mark it `map hook`), loaded only when the tab opens; `site/map/us.json` + `site/data/map-land.json` (public-domain Natural Earth) are the fallback base. Keep the list under the map mirroring the dots (same filter and hour), 44 px targets, privacy-safe trip routes (codes only) and no "%" in Traveler mode. Check rows live in `site/map/check.js`; hooks are marked `map hook`. Radar overlay (Overlays → Radar, off by default, saved in `awx-map`): `site/map/mrms.js` draws IEM's quality-controlled MRMS tiles (`mrms::lcref-<time>` from `lcref.json`, CORS-open) decoded to dBZ and redrawn in one neutral ramp (never the risk colours) into the base canvas under the lines and labels; current hour only, refreshed every 2 min, CONUS only.
